# 02 — 组件开发规范

> 参考 Wot UI v2、TDesign、NutUI 等高星 UI 库的组件设计模式，结合 uni-app 双端特性制定。

## 组件分类与层级

| 层级 | 名称     | 职责                     | 示例                                        | 依赖                   |
| ---- | -------- | ------------------------ | ------------------------------------------- | ---------------------- |
| L0   | 基础组件 | 单一功能、无业务语义     | `wd-button`、`wd-input`                     | Wot UI v2 原生         |
| L1   | 功能组件 | 组合基础组件，带通用功能 | `PageContainer`、`FormField`、`ImageUpload` | 依赖 L0                |
| L2   | 业务组件 | 包含业务逻辑和领域语义   | `ResourceCard`、`TaskItem`                  | 依赖 L0/L1 + API/Store |
| L3   | 页面区块 | 页面内的独立区块，可组合 | `HomeRoleA`、`HomeRoleB`                    | 依赖 L0/L1/L2          |

**规则**：下层组件不得反向依赖上层组件；同层组件之间尽量不互相依赖。

## 组件文件结构

### 单文件组件（简单组件）

```
components/
└─ ResourceCard.vue         # 单文件，模板+脚本+样式
```

### 复杂组件（多文件）

```
components/
└─ image-upload/
   ├─ ImageUpload.vue      # 主组件（对外暴露）
   ├─ ImageUploadItem.vue  # 子组件（内部使用，不对外）
   ├─ useUpload.ts         # 组合式逻辑
   └─ types.ts             # 类型定义
```

规则：**超过 200 行的组件考虑拆分**；内部子组件以相同前缀命名，不单独注册 easycom。

## Vue 3 组件写法

### 统一使用 `<script setup lang="ts">`

```vue
<script setup lang="ts">
// Props 定义
interface Props {
  /** 资源标题 */
  name: string
  /** 资源状态 */
  status?: "draft" | "published" | "archived"
  /** 是否可点击 */
  clickable?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  status: "draft",
  clickable: false,
})

// Emits 定义
interface Emits {
  (e: "click", id: string): void
  (e: "update:visible", visible: boolean): void
}

const emit = defineEmits<Emits>()

// 暴露给父组件的方法/属性
defineExpose({
  reset() {
    /* ... */
  },
})
</script>
```

**禁止写法**：

- 禁止使用 `setup()` 选项式 API（老项目迁移除外）
- 禁止 `any` 类型（除非明确标记并附注释说明原因）
- 禁止在 `script setup` 中出现未使用的 import

## Props 设计原则

1. **单一职责**：每个 prop 只控制一个行为，避免 prop 组合爆炸。
2. **默认值友好**：非必填 prop 必须有合理默认值，组件在无 props 时也能正常展示。
3. **布尔 prop 用 is/has/can 前缀**：`isLoading`、`hasBorder`、`canEdit`。
4. **枚举 prop 用联合类型**：`type?: 'primary' | 'success' | 'warning' | 'danger'`。
5. **对象/数组 prop 默认值用函数**（Vue 3 自动处理，保持习惯）。
6. **prop 名用 camelCase**，模板中用 kebab-case 绑定。

## Events 设计原则

1. **事件名用动词开头**：`click`、`change`、`confirm`、`cancel`、`update:modelValue`。
2. **支持 v-model**：可双向绑定的值用 `update:*` 事件模式。
3. **事件参数保持一致**：同类组件的事件参数顺序和类型保持统一。
4. **不传递原始 DOM 事件**：小程序端无 DOM，用 uni-app 事件对象或业务数据。

## Slots 设计原则

1. **默认 slot 放主要内容**，命名 slot 用语义化名称：`header`、`footer`、`prefix`、`suffix`。
2. **作用域 slot 传数据**：当 slot 需要访问组件内部数据时使用作用域 slot。
3. **slot 数量控制**：一个组件的命名 slot 不超过 5 个，超过则考虑拆分组件。

## 组件通信

| 场景         | 方案                                       |
| ------------ | ------------------------------------------ |
| 父 → 子      | Props                                      |
| 子 → 父      | Emit events                                |
| 兄弟         | 共同父组件状态提升 + props/events          |
| 跨多层       | Provide / Inject（慎用，优先考虑状态管理） |
| 全局共享状态 | Pinia store                                |

**禁止**：通过 `$parent` / `$children` 直接访问父子组件实例。

## Easycom 注册规则

1. **跨页面复用的 L1/L2 组件**配置 easycom 自动注册，页面内直接使用无需 import。
2. **单页面内部子组件**不注册 easycom，在页面内手动 import。
3. easycom 规则在 `pages.json` 的 `easycom.custom` 中配置，使用前缀匹配：

```json
{
  "easycom": {
    "autoscan": true,
    "custom": {
      "^wd-(.*)": "@wot-ui/ui/components/wd-$1/wd-$1.vue",
      "^Home(.*)": "@/components/home/Home$1.vue",
      "^Layout(.*)": "@/components/layout/Layout$1.vue",
      "^Form(.*)": "@/components/form/Form$1.vue"
    }
  }
}
```

4. **不要用 unplugin-vue-components 替代 easycom**：小程序端不兼容，会导致双端行为不一致。

## 组件样式规范

1. **优先使用 UnoCSS 原子类**，减少 scoped 样式。
2. 必须使用 scoped 样式时，用 BEM 命名：`.component-name__element--modifier`。
3. **禁止使用 `*` 通配符、属性选择器、`:hover` 伪类**（WXSS 不支持）。
4. 尺寸单位用 `rpx`（UnoCSS preset-weapp 自动处理）。
5. 组件根元素加唯一 class 前缀，避免样式泄漏。

## 可访问性（a11y）

1. 按钮/可点击元素必须有语义：`<button>` 或 `role="button"`。
2. 图标按钮必须有 `aria-label` 或 `title`。
3. 表单控件必须关联 label。
4. 颜色对比度满足 WCAG AA 标准（正文对比度 ≥ 4.5:1）。

## 性能要点

1. **长列表用虚拟滚动**：Wot UI v2 的 `wd-virtual-list` 或 uni-app `scroll-view` + 懒渲染。
2. **图片懒加载**：`<image lazy-load>`（H5/小程序均支持）。
3. **避免 v-for 内复杂计算**：用 `computed` 预计算。
4. **组件按需挂载**：条件渲染用 `v-if` 控制重型组件初始化时机。
5. **减少响应式数据**：不需要响应式的常量用 `const` 或 `markRaw`。

## 组件文档

每个公共组件（L1 及以上）在文件开头用 JSDoc 说明：

```ts
/**
 * 资源卡片组件
 * @description 展示资源基本信息和资源状态，支持点击查看详情
 * @example
 * <ResourceCard
 *   name="张三"
 *   status="published"
 *   @click="handleClick"
 * />
 */
```
