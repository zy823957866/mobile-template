# 13 — 错误处理与日志规范

> 基于企业级应用错误处理最佳实践，参考 vue-vben-admin、TDesign 等项目的异常处理模式，结合 uni-app 双端特性制定。

## 错误分类与处理原则

### 错误类型

| 类型         | 说明                             | 处理层级                   |
| ------------ | -------------------------------- | -------------------------- |
| 网络错误     | 断网、超时、DNS 失败             | request 层统一处理         |
| HTTP 错误    | 4xx、5xx 状态码                  | request 层按状态码处理     |
| 业务错误     | 接口 code 非 0                   | request 层抛出，业务层处理 |
| 前端异常     | JS 运行时错误、Promise rejection | 全局错误捕获               |
| 页面渲染错误 | 组件渲染异常                     | 组件级错误边界             |

### 处理原则

1. **统一入口**：所有网络请求错误由 `request.ts` 统一拦截处理。
2. **用户友好**：错误消息清晰易懂，不暴露技术细节。
3. **可恢复性**：提供重试、返回等操作，不让用户卡死在错误页。
4. **可追溯性**：关键错误上报日志，便于排查。
5. **分层处理**：底层处理通用错误，上层处理业务特有错误。

## 网络请求错误处理

### request 层统一处理

```ts
// api/request.ts

/** 错误码映射 */
const ERROR_MESSAGES: Record<number, string> = {
  400: "请求参数错误",
  401: "登录已过期，请重新登录",
  403: "无权限访问",
  404: "请求的资源不存在",
  429: "请求过于频繁，请稍后再试",
  500: "服务器内部错误",
  502: "网关错误",
  503: "服务不可用",
  504: "网关超时",
}

function handleError(statusCode: number, message?: string): string {
  // 上报错误日志
  reportError({ type: "api", statusCode, message })

  // 401 特殊处理：清除登录态 + 跳登录
  if (statusCode === 401) {
    removeToken()
    removeStoredRole()
    uni.reLaunch({ url: "/pages/login/login" })
    return ERROR_MESSAGES[401]
  }

  return message || ERROR_MESSAGES[statusCode] || "请求失败，请稍后重试"
}
```

### 业务错误处理

```ts
// 页面/业务层
async function handleSubmit() {
  try {
    await submitForm(formData)
    uni.showToast({ title: "提交成功", icon: "success" })
  } catch (err: any) {
    // 业务错误：request 层已 showToast，此处处理逻辑
    // 如需自定义错误提示，传 silent: true 给 request
    if (err.code === "DUPLICATE_RESOURCE") {
      // 特定业务错误的特殊处理
      showDuplicateDialog()
    }
  }
}
```

### 重试机制

```ts
// composables/ui/useRetry.ts

interface RetryOptions {
  retries?: number
  delay?: number
  shouldRetry?: (error: Error) => boolean
}

/**
 * 带重试的请求封装
 * 默认网络错误重试 2 次，间隔 1s
 */
export async function withRetry<T>(fn: () => Promise<T>, options: RetryOptions = {}): Promise<T> {
  const { retries = 2, delay = 1000, shouldRetry = () => true } = options

  try {
    return await fn()
  } catch (err) {
    if (retries > 0 && shouldRetry(err as Error)) {
      await new Promise((resolve) => setTimeout(resolve, delay))
      return withRetry(fn, { retries: retries - 1, delay: delay * 2, shouldRetry })
    }
    throw err
  }
}
```

## 全局错误捕获

### App.vue 中配置

```ts
// App.vue onLaunch 中

// 全局未捕获的 Promise rejection
uni.onUnhandledRejection((res) => {
  console.error("[UnhandledRejection]", res.reason)
  reportError({ type: "unhandled_rejection", reason: res.reason })
})

// 全局错误
if (typeof uni.onError === "function") {
  uni.onError((err: string) => {
    console.error("[GlobalError]", err)
    reportError({ type: "global_error", message: err })
  })
}
```

### Vue 应用级错误

```ts
// main.ts
const app = createSSRApp(App)

app.config.errorHandler = (err, instance, info) => {
  console.error("[Vue Error]", err, info)
  reportError({
    type: "vue_error",
    message: err instanceof Error ? err.message : String(err),
    stack: err instanceof Error ? err.stack : undefined,
    info,
  })
}
```

## 页面级错误处理

### 错误状态展示

每个数据加载页面必须处理三种状态：loading / error / success。

使用 `LayoutPageContainer` 统一封装：

```vue
<template>
  <LayoutPageContainer :loading="loading" :error="error" :error-text="errorText" @retry="loadData">
    <!-- 页面内容 -->
  </LayoutPageContainer>
</template>
```

### 空状态

列表数据为空时展示空状态，不要显示空白页面：

```vue
<template>
  <view v-if="list.length === 0 && !loading && !error" class="empty-state">
    <wd-empty description="暂无数据" />
  </view>
</template>
```

## 错误提示规范

### Toast 提示

用于轻量级错误反馈，自动消失：

```ts
// 成功
uni.showToast({ title: "操作成功", icon: "success", duration: 1500 })

// 错误
uni.showToast({ title: errorMsg, icon: "none", duration: 2000 })

// 加载中
uni.showLoading({ title: "加载中...", mask: true })
```

### Modal 弹窗

用于需要用户确认的重要错误：

```ts
uni.showModal({
  title: "提示",
  content: "网络连接异常，请检查网络设置后重试",
  confirmText: "重试",
  cancelText: "取消",
  success: (res) => {
    if (res.confirm) {
      retry()
    }
  },
})
```

### 提示使用原则

| 场景               | 方式            | 时长     |
| ------------------ | --------------- | -------- |
| 操作成功           | Toast (success) | 1.5s     |
| 操作失败（可恢复） | Toast (none)    | 2s       |
| 严重错误           | Modal           | 手动关闭 |
| 加载中             | Loading         | 手动关闭 |
| 表单校验错误       | 内联错误文案    | 持续展示 |

## 日志上报

### 上报接口（预留）

```ts
// utils/logger.ts

interface LogData {
  type: "api" | "vue_error" | "global_error" | "unhandled_rejection" | "custom"
  message?: string
  [key: string]: unknown
}

/**
 * 上报错误日志
 * 生产环境上报到监控平台，开发环境只输出 console
 */
export function reportError(data: LogData): void {
  // 开发环境只打日志
  if (import.meta.env.DEV) {
    console.error("[Error Report]", data)
    return
  }

  // 生产环境上报（预留接口，接入监控平台时替换）
  // 例如：sentry、fundebug、微信小程序后台等
  try {
    // TODO: 接入监控平台
    // uni.request({ url: '/api/log/report', method: 'POST', data })
  } catch (e) {
    // 上报失败静默处理，不能影响业务
  }
}

/**
 * 埋点上报（行为日志）
 */
export function trackEvent(event: string, params?: Record<string, unknown>): void {
  if (import.meta.env.DEV) {
    console.log("[Track]", event, params)
    return
  }
  // TODO: 接入埋点系统
}
```

### 上报内容规范

上报信息包含但不限于：

- 错误类型
- 错误消息
- 错误堆栈（如果有）
- 用户 ID（如果已登录）
- 设备信息（平台、版本、系统）
- 当前页面路径
- 发生时间

## 敏感信息处理

1. **不上报敏感数据**：密码、身份证号、token 等不上报到日志系统。
2. **数据脱敏**：手机号、姓名等敏感信息上报时脱敏。
3. **本地日志**：`console.log` 中也不要输出敏感信息。

```ts
function maskPhone(phone: string): string {
  return phone.replace(/(\d{3})\d{4}(\d{4})/, "$1****$2")
}
```

## 开发环境调试

1. **开发环境详细日志**：console 输出完整错误信息、请求参数、响应数据。
2. **生产环境精简输出**：只输出必要的错误，关闭 console.log。
3. **VConsole**：H5 端可使用 vConsole 进行移动端调试（开发环境）。
