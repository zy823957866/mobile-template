# 11 — 工程化与代码质量规范

> 基于 vue-vben-admin、vitesse 等高星项目的工程化实践，结合本项目工具链制定。

## 工具链概览

| 工具        | 用途         | 配置文件                             |
| ----------- | ------------ | ------------------------------------ |
| Vite        | 构建工具     | `vite.config.ts`                     |
| TypeScript  | 类型检查     | `tsconfig.json`                      |
| ESLint      | 代码质量检查 | `eslint.config.js`                   |
| Prettier    | 代码格式化   | `.prettierrc`                        |
| Stylelint   | 样式检查     | `stylelint.config.js`                |
| Husky       | Git Hooks    | `.husky/`                            |
| lint-staged | 增量 lint    | `package.json` 的 `lint-staged` 字段 |
| Commitlint  | 提交信息规范 | `commitlint.config.js`               |

## Git 工作流

### 分支模型

```
main         # 生产分支，保护分支，只能通过 PR 合并
└─ develop   # 开发分支，日常开发基于此
   └─ feature/xxx   # 功能分支
   └─ bugfix/xxx    # Bug 修复分支
   └─ hotfix/xxx    # 线上紧急修复（从 main 切出）
```

### 分支命名

| 类型     | 前缀        | 示例                        |
| -------- | ----------- | --------------------------- |
| 功能     | `feature/`  | `feature/resource-register` |
| Bug 修复 | `bugfix/`   | `bugfix/login-error`        |
| 紧急修复 | `hotfix/`   | `hotfix/token-expire`       |
| 重构     | `refactor/` | `refactor/api-layer`        |
| 文档     | `docs/`     | `docs/update-readme`        |

### 提交信息规范

采用 [Conventional Commits](https://www.conventionalcommits.org/)：

```
<type>(<scope>): <subject>

<body>

<footer>
```

#### type 类型

| type       | 说明                             |
| ---------- | -------------------------------- |
| `feat`     | 新功能                           |
| `fix`      | 修复 bug                         |
| `docs`     | 文档变更                         |
| `style`    | 代码格式（不影响代码运行）       |
| `refactor` | 重构（不是新增功能也不是修 bug） |
| `perf`     | 性能优化                         |
| `test`     | 测试相关                         |
| `build`    | 构建系统或外部依赖变更           |
| `ci`       | CI 配置变更                      |
| `chore`    | 其他杂项                         |
| `revert`   | 回滚提交                         |

#### 示例

```
feat(resource): 添加资源登记表单

- 实现姓名、手机号、组织等字段
- 接入 wot-form 校验
- 对接资源创建接口

Closes #123
```

## ESLint 规则

基于 `@eslint/js` + `typescript-eslint` + `eslint-plugin-vue` 配置。

### 核心规则

```js
// 关键规则（示意，具体见 eslint.config.js）
{
  // Vue 3 推荐规则集
  'vue/vue3-recommended': 'error',
  // 禁止使用 any
  '@typescript-eslint/no-explicit-any': 'warn',
  // 禁止未使用的变量
  '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
  // 优先使用 const
  'prefer-const': 'error',
  // 禁止 var
  'no-var': 'error',
  // 禁止 console.log（生产构建）
  'no-console': ['warn', { allow: ['warn', 'error'] }],
  // 禁止 debugger
  'no-debugger': 'error',
}
```

### 运行命令

```bash
npm run lint          # 检查
npm run lint:fix      # 自动修复
```

## Stylelint 规则

基于 `stylelint-config-standard` + `stylelint-config-recommended-scss`。

### 关键规则

1. 禁止使用 `!important`
2. 禁止空规则块
3. 颜色小写、十六进制颜色简写
4. 禁止重复的选择器
5. 单位小写

### 运行命令

```bash
npm run stylelint          # 检查
npm run stylelint:fix      # 自动修复
```

## Husky + lint-staged

提交前自动检查增量代码：

```json
// package.json
{
  "lint-staged": {
    "*.{js,mjs,cjs,ts,tsx,vue}": ["eslint --fix", "prettier --write"],
    "*.{css,scss,vue}": ["stylelint --fix"],
    "*.{json,jsonc,md,yml,yaml}": ["prettier --write"]
  }
}
```

### Hooks

- `pre-commit`：运行 lint-staged
- `commit-msg`：运行 commitlint 校验提交信息
- `pre-push`：运行 type-check（可选）

## TypeScript 规范

### 类型定义

1. **禁止滥用 `any`**：尽量用 `unknown` 或具体类型代替。
2. **优先用 interface 定义对象类型**：API 响应、props 等用 interface。
3. **联合类型优于枚举**：`type Status = 'pending' | 'approved'` 比 `enum Status` 更轻量。
4. **类型文件组织**：
   - API 类型：`src/api/types/*.ts`
   - 组件 Props：组件文件内定义
   - 全局类型：`src/types/*.ts`
5. **函数必须标注返回值类型**：导出的公共函数必须有返回类型。

### tsconfig 关键配置

```json
{
  "strict": true,
  "noImplicitAny": true,
  "strictNullChecks": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true
}
```

### 类型检查

```bash
npm run type-check
```

## 导入与路径规范

1. **绝对路径导入**：用 `@/` 别名（`@/components/...`、`@/utils/...`），不用相对路径 `../../`。
2. **文件命名**：见 [01-项目架构与目录规范.md](./01-项目架构与目录规范.md)。
3. **导入顺序**：
   1. Vue / 第三方库
   2. @/ 别名导入（store、api、utils、components）
   3. 相对路径导入（同目录文件）
   4. 样式导入

```ts
// 正确示例
import { ref, computed } from "vue"
import { useAuthStore } from "@/store/auth"
import { formatDate } from "@/utils/format"
import { usePagination } from "./usePagination"
import "./style.scss"
```

## 注释规范

### 文件头部注释

```ts
/**
 * 资源列表 composable
 * @description 封装资源列表的分页、刷新、加载逻辑
 */
```

### 函数注释

```ts
/**
 * 格式化日期为 YYYY-MM-DD
 * @param date - 日期字符串或 Date 对象
 * @param locale - 语言环境
 * @returns 格式化后的日期字符串
 * @example
 * formatDate('2024-01-01T00:00:00Z') // '2024-01-01'
 */
export function formatDate(date: string | Date, locale?: string): string {
  // ...
}
```

### 行内注释

使用 `//` 单行注释，放在被注释代码上方，解释「为什么」而不是「做什么」。

## 环境变量规范

1. **命名约定**：`VITE_` 前缀 + 大写下划线 `VITE_API_BASE_URL`。
2. **环境文件**：
   - `.env.development` — 开发环境
   - `.env.production` — 生产环境
   - `.env.staging` — 预发布环境（可选）
3. **类型声明**：在 `src/env.d.ts` 中声明环境变量类型。
4. **不要提交敏感信息**：密钥、密码等不要放在 `.env` 文件中（会被打包）。

## 构建与发布

### 构建命令

```bash
npm run build:h5          # 构建 H5
npm run build:mp-weixin   # 构建微信小程序
```

### 构建产物

| 平台       | 产物路径                |
| ---------- | ----------------------- |
| H5         | `dist/build/h5/`        |
| 微信小程序 | `dist/build/mp-weixin/` |

### 发布流程

1. 更新版本号（`package.json` 的 `version` 字段）
2. 执行 type-check + lint + build
3. H5 部署到静态服务器 / CDN
4. 小程序上传到微信公众平台
5. 生成 release note

## Code Review 检查清单

提交 PR 前自查：

- [ ] 功能是否符合需求描述
- [ ] 是否有类型错误（`npm run type-check` 通过）
- [ ] 是否有 lint 错误（`npm run lint` 通过）
- [ ] H5 端是否正常运行
- [ ] 小程序端是否正常运行
- [ ] 国际化是否完整（zh-CN / en 及所有已启用语言）
- [ ] 是否有性能问题（大列表、频繁渲染等）
- [ ] 是否有安全问题（XSS、敏感信息泄漏等）
