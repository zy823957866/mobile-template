# 10 — 性能优化规范

> 基于微信小程序官方性能优化指南、uni-app 官方优化建议，以及高星项目的工程实践制定。

## 性能指标参考

| 指标                | 目标值  | 说明                             |
| ------------------- | ------- | -------------------------------- |
| 首屏加载时间        | < 2s    | 从启动到首屏渲染完成             |
| 页面切换            | < 300ms | 页面跳转白屏时间                 |
| 长列表帧率          | ≥ 50fps | 滚动时的流畅度                   |
| 主包体积            | < 1.5MB | 微信小程序主包上限 2MB，预留缓冲 |
| 总包体积            | < 15MB  | 微信小程序总包上限 20MB          |
| 单次 setData 数据量 | < 256KB | 小程序 setData 建议上限          |

## 启动性能

### 主包优化

1. **分包加载**：各业务页面全部进入对应分包，主包只留 tab 页和公共页。
2. **公共依赖评估**：仅在主包保留核心依赖（pinia、vue-i18n、Wot UI v2），业务专用依赖放分包。
3. **图片资源优化**：
   - tabBar 图标压缩到 3KB 以内
   - 非必要图片改用 CSS 绘制或 iconfont
   - 大图放 CDN，不打包进项目
4. **静态资源压缩**：
   - PNG 用 tinypng 压缩
   - SVG 用 svgo 优化

### 首屏渲染优化

1. **首屏数据优先请求**：首屏关键接口先请求，非关键数据延迟到 `onReady` 后加载。
2. **骨架屏**：列表页、详情页使用骨架屏替代 loading 转圈，提升感知速度。
3. **首屏内容最小化**：首屏只渲染可视区域内容，下方内容懒加载。
4. **App.vue 精简**：`onLaunch` 中不要放耗时操作，必要操作延后到首屏渲染后。

## 列表性能

### 长列表优化

1. **虚拟列表**：超过 50 条的列表使用虚拟滚动（Wot UI v2 的 `wd-virtual-list` 或 uni-app `recycle-view`）。
2. **分页加载**：每页 20-50 条，上拉加载更多，不一次性加载全部数据。
3. **图片懒加载**：`<image lazy-load>` 或 `wd-img` 的 `lazy` 属性。
4. **列表项 key**：`v-for` 必须加 `:key`，用唯一 id 不用 index。

```vue
<!-- ✅ 正确 -->
<view v-for="item in list" :key="item.id">

<!-- ❌ 错误 -->
<view v-for="(item, index) in list" :key="index">
```

### 下拉刷新 + 上拉加载

```ts
// 使用 usePagination composable 统一处理
// composables/list/usePagination.ts

import { ref } from "vue"

interface UsePaginationOptions<T> {
  fetchFn: (params: { page: number; pageSize: number }) => Promise<{ list: T[]; total: number }>
  pageSize?: number
  immediate?: boolean
}

export function usePagination<T>(options: UsePaginationOptions<T>) {
  const { fetchFn, pageSize = 20, immediate = true } = options

  const list = ref<T[]>([])
  const total = ref(0)
  const page = ref(1)
  const loading = ref(false)
  const finished = ref(false)
  const error = ref<Error | null>(null)

  async function loadMore() {
    if (loading.value || finished.value) return
    loading.value = true
    error.value = null
    try {
      const data = await fetchFn({ page: page.value, pageSize })
      list.value.push(...data.list)
      total.value = data.total
      finished.value = list.value.length >= data.total
      page.value++
    } catch (err) {
      error.value = err as Error
    } finally {
      loading.value = false
    }
  }

  async function refresh() {
    page.value = 1
    list.value = []
    finished.value = false
    await loadMore()
    uni.stopPullDownRefresh()
  }

  if (immediate) {
    loadMore()
  }

  return {
    list,
    total,
    loading,
    finished,
    error,
    loadMore,
    refresh,
  }
}
```

## 内存管理

1. **及时清理定时器**：`onUnload` / `onHide` 中清除 `setInterval`、`setTimeout`。
2. **取消未完成请求**：页面卸载时取消未完成的网络请求（用 requestTask.abort()）。
3. **移除事件监听**：`onUnload` 中移除 `uni.$on` 事件监听。
4. **大对象及时释放**：图片、大列表数据在页面卸载时置空。

```vue
<script setup>
let timer: ReturnType<typeof setInterval> | null = null

onLoad(() => {
  timer = setInterval(() => { /* ... */ }, 1000)
})

onUnload(() => {
  if (timer) {
    clearInterval(timer)
    timer = null
  }
})
</script>
```

## 渲染性能

### 减少 setData 调用

1. **合并数据更新**：多个状态变化合并到一次更新，不要分开赋值。
2. **避免频繁更新**：输入框输入等高频操作防抖处理。
3. **非展示数据不放响应式**：用 `markRaw` 或普通变量存储不需要渲染的数据。

### 减少节点数量

1. **避免不必要的嵌套**：能用 `view` 解决的不用多层嵌套。
2. **CSS 替代节点**：能用伪元素、背景图实现的效果不加额外节点。
3. **条件渲染**：不显示的内容用 `v-if`（不是 `v-show`），减少节点数。

### 小程序端特有优化

1. **`setData` 数据最小化**：只更新变化的字段，用路径更新（Vue 3 自动处理部分）。
2. **避免频繁触发 `setData`**：滚动事件、拖拽事件中注意节流。
3. **自定义组件性能模式**：如开发自定义组件，启用纯数据字段优化。

## 图片性能

1. **选择合适格式**：
   - 图标：PNG-8 或 SVG
   - 照片：JPEG / WebP（小程序端支持 WebP）
2. **尺寸适配**：图片尺寸不超过展示尺寸的 2 倍（2x 屏）。
3. **CDN 图片处理**：使用 CDN 的图片裁剪/压缩参数（如 `?imageView2/2/w/400`）。
4. **占位图**：列表图用低质量占位图或骨架屏，加载完成后替换。

## 包体积优化

### 代码层面

1. **Tree Shaking**：使用 ES Module 写法，避免 `require()` 动态导入。
2. **按需引入**：Wot UI v2 通过 easycom 自动按需引入，不用手动处理。
3. **移除无用代码**：定期清理未使用的组件、工具函数。
4. **大依赖替代**：
   - 日期处理：不用 moment.js，用轻量库或原生 Date
   - 工具库：不用 lodash 全量，用按需导入或手写小工具

### 构建配置

1. **生产构建压缩**：Vite 生产模式自动启用 terser 压缩。
2. **Source Map**：生产环境不生成 source map（或单独存放）。
3. **分包预下载**：配置 `preloadRule`，在合适时机预下载分包。

```json
// pages.json
{
  "preloadRule": {
    "pages/index/index": {
      "network": "wifi",
      "packages": ["pages/package-a", "pages/package-b"]
    }
  }
}
```

## 网络优化

1. **请求合并**：同一页面多个接口可合并为一个批量接口（后端配合）。
2. **接口缓存**：不常变的数据（如字典、配置）做本地缓存。
3. **HTTP/2**：后端接口启用 HTTP/2，多路复用。
4. **CDN 加速**：静态资源走 CDN。
5. **Gzip / Brotli**：H5 端启用压缩。

## 性能监控

1. **小程序性能面板**：开发阶段开启性能面板（微信开发者工具 → 详情 → 性能面板）。
2. **关键路径打点**：在 `App.vue onLaunch`、首页 `onReady` 等关键节点打点。
3. **异常监控**：接入小程序后台性能监控或第三方 APM。
4. **定期 Review**：每月检查一次小程序后台的性能数据。

## 常见性能坑

1. **滥用 `watch`**：避免 deep watch 大对象，监听具体字段。
2. **模板中复杂计算**：模板中只放简单表达式，复杂计算用 `computed`。
3. **`v-show` 用在大块内容上**：频繁切换的用 `v-show`，不频繁的用 `v-if`。
4. **列表项中用 `v-if` / `v-for` 同级**：Vue 3 中 `v-if` 和 `v-for` 同时使用时 `v-if` 优先，可能不符合预期。用 computed 先过滤。
5. **全局事件未清理**：`uni.$on` 必须有对应的 `uni.$off`。
