# 15 — 安全规范

> 基于 Web 安全最佳实践（OWASP）、微信小程序安全指南，以及企业级应用安全规范制定。

## 认证与授权

### Token 管理

1. **存储安全**：
   - token 存储在 `uni.setStorageSync` 中，key 为 `app.token`
   - 小程序端 storage 由微信沙箱保护
   - H5 端不使用 localStorage 存敏感信息（uni storage 在 H5 端底层是 localStorage，注意 XSS 风险）
2. **传输安全**：
   - 生产环境必须使用 HTTPS
   - token 通过 `Authorization: Bearer {token}` 请求头传递，不放在 URL 中
3. **过期处理**：
   - 401 时自动清除 token 并跳转登录页
   - 不要在前端存储 refresh_token（增加泄漏风险），由后端处理或通过接口刷新
4. **登出清理**：
   - 登出时清除 token、role、profile 等所有用户相关数据
   - 清除后跳转到登录页

### 权限控制

1. **角色判断**：前端基于 `auth.role` 做 UI 级别的权限控制，后端做接口级权限校验。
2. **前端权限不做安全保障**：仅控制按钮/菜单展示，后端必须独立校验权限。
3. **路由守卫**：受保护页面在 `onLoad` 中调用 `ensureAuthenticated()` 检查登录态。
4. **接口权限**：每个接口后端验证 token 有效性和角色权限。

## 输入验证与输出编码

### 输入验证

1. **所有用户输入必须校验**：前端做格式校验，后端做安全校验。
2. **校验规则**：
   - 手机号：`/^1[3-9]\d{9}$/`
   - 邮箱：标准 email 格式
   - 身份证号：长度 + 格式校验
   - 姓名：限制长度和字符集（中文、英文、空格、点）
   - 文本输入：限制最大长度，防止超长输入
3. **类型转换**：数字类型字段做显式转换，不要依赖隐式类型转换。

### XSS 防护

1. **Vue 模板自动转义**：使用 `{{ }}` 插值时 Vue 自动转义，不要用 `v-html` 渲染用户输入内容。
2. **富文本场景**：
   - 尽量不用 `v-html`
   - 如必须使用，先通过 DOMPurify 等库净化（H5 端）
   - 小程序端不支持 `v-html`，使用 `rich-text` 组件且内容必须经过后端净化
3. **URL 安全**：用户输入的 URL 必须做协议白名单校验（只允许 http/https）。

### CSRF 防护

1. **小程序端**：由微信域名校验和小程序沙箱保障，天然免疫 CSRF。
2. **H5 端**：
   - 使用 JWT + Authorization header 模式，不依赖 cookie 认证
   - 后端做 CORS 域名白名单
   - 敏感操作接口加请求签名或 token 校验

## 数据安全

### 敏感数据处理

1. **敏感数据脱敏展示**：
   - 手机号：`138****5678`
   - 身份证号：`320***********1234`
   - 邮箱地址：`a***@example.com`
   - 姓名：`张*` 或 `*三`
2. **敏感数据传输**：
   - 密码等敏感信息在传输前可做前端加密（如 RSA），但不能替代 HTTPS
   - 身份证号、银行卡号等在请求体中传输，不在 URL 中
3. **敏感数据存储**：
   - 本地存储只存 token，不存密码、身份证号等敏感信息
   - token 也有泄漏风险，设置合理的过期时间

### 日志安全

1. **日志中不输出敏感信息**：console.log 中不要打印密码、token、身份证号等。
2. **错误上报脱敏**：上报错误日志前，对敏感字段做脱敏处理。

## 第三方依赖安全

1. **依赖审计**：定期运行 `npm audit` 检查依赖漏洞。
2. **锁定版本**：使用 lockfile（pnpm-lock.yaml）锁定依赖版本。
3. **慎用未知来源依赖**：引入新依赖前检查：
   - GitHub stars 和维护状态
   - 最近更新时间
   - 下载量
   - 是否有已知漏洞
4. **生产构建安全**：
   - 不把源码 map 部署到生产环境
   - 移除开发环境代码（Vite 自动处理 `import.meta.env.DEV` 判断）

## 小程序安全

### 域名白名单

1. **request 合法域名**：在微信公众平台配置 request 域名白名单。
2. **uploadFile / downloadFile 合法域名**：上传下载域名也要配置。
3. **webview 域名**：如使用 web-view 组件，配置业务域名。

### 代码保护

1. **开启代码保护**：微信开发者工具 → 详情 → 本地设置 → 代码保护。
2. **代码混淆**：生产构建时开启代码压缩和混淆。
3. **敏感逻辑放后端**：核心业务逻辑和安全校验放在后端，前端只做展示和交互。

### 用户隐私

1. **用户隐私协议**：收集用户信息前展示隐私协议并获取同意。
2. **权限申请**：获取用户信息（头像、昵称、手机号）时明确告知用途。
3. **数据最小化**：只收集必要的用户信息。

## H5 安全

### CSP（内容安全策略）

如部署环境支持，配置 CSP 响应头：

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:;
```

### X-Frame-Options

防止点击劫持：

```
X-Frame-Options: DENY
```

### HTTP 安全头

生产环境 Nginx 配置以下安全头：

- `X-Content-Type-Options: nosniff`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`

## 开发规范

1. **不要在代码中硬编码密钥、密码、token**。
2. **环境变量不存敏感信息**：VITE_ 开头的变量会被打包进客户端代码。
3. **.env 文件不提交到 git**（`.gitignore` 中排除）。
4. **密钥等敏感配置放后端**：前端不处理敏感配置。
5. **定期安全 review**：新功能上线前做安全自查。

## 安全检查清单

上线前检查：

- [ ] 所有接口走 HTTPS
- [ ] 用户输入都有前端校验
- [ ] 没有使用 `v-html` 渲染用户输入
- [ ] 敏感数据在展示和日志中都已脱敏
- [ ] token 过期后正确跳转登录
- [ ] 没有在代码中硬编码密钥或密码
- [ ] 生产构建不包含 source map
- [ ] 小程序后台已配置合法域名
- [ ] 第三方依赖无高危漏洞
- [ ] 后端有独立的权限校验（不依赖前端控制）
