# 06 — 国际化规范（多语言）

> 基于 vue-i18n 官方最佳实践，适用于默认中英双语、可按配置扩展语言的移动端模版。

## 语言策略

| 语言     | code      | 默认启用 |
| -------- | --------- | -------- |
| 简体中文 | `zh-CN`   | ✅ 默认  |
| 英文     | `en`      | ✅       |
| 其他语言 | 对应 code | 按配置   |

- 默认语言：`zh-CN`
- 回退语言：`zh-CN`（缺失翻译时回退）
- 语言切换入口：「我的」页面

## 技术选型

- **i18n 库**：vue-i18n v9（Composition API 模式，`legacy: false`）
- **持久化**：`uni.setStorageSync`，key = `app.locale`
- **语言包格式**：TypeScript 对象（.ts 文件，便于类型约束）

## 语言包结构

```
locales/
├─ index.ts          # i18n 实例、工具函数
├─ zh-CN.ts          # 中文
└─ en.ts             # 英文；新增语言时按此结构扩展
```

### 命名规则

1. **key 用小写 + 点分隔层级**：`resource.status.draft`
2. **动词/名词清晰区分**：按钮文案用动词，标题用名词
3. **按领域分组**：`common`、`auth`、`resource`、`home` 等
4. **状态值嵌套**：如 `resource.status.draft`
5. **占位符用 `{{param}}`**：vue-i18n 标准格式

## 在组件中使用

### 基本用法

```vue
<script setup lang="ts">
import { useI18n } from "vue-i18n"

// 已通过 unplugin-auto-import 自动导入，实际可省略上一行
const { t } = useI18n()
</script>

<template>
  <!-- 简单文本 -->
  <view>{{ t("common.confirm") }}</view>

  <!-- 带参数 -->
  <view>{{ t("home.welcome", { name: userName }) }}</view>
</template>
```

### 切换语言

```ts
import { setAppLocale } from "@/locales"

function changeLanguage(locale: "zh-CN" | "en" | string) {
  setAppLocale(locale)
}
```

## 按配置过滤语言

### getSupportedLocales 函数

```ts
// locales/index.ts
export function getSupportedLocales(context?: Record<string, unknown>) {
  const enabledLocales = context?.enabledLocales
  return Array.isArray(enabledLocales) ? enabledLocales : ["zh-CN", "en"]
}
```

**规则**：

1. 所有语言选择 UI 必须调用 `getSupportedLocales(context)` 过滤。
2. 语言可用性由应用配置决定，不在组件中写死。
3. URL/手动输入未启用的 locale 时，自动回退到默认语言。

## 新增翻译的工作流

1. 在 `zh-CN.ts` 中新增 key 和中文文案。
2. 同步在所有已启用语言包中新增对应 key。
3. 各语言包的 key 结构必须完全一致。
4. 如暂未翻译，先用英文占位，加 `// TODO: translate` 注释。

**禁止**：

- 禁止只更新一个语言包
- 禁止硬编码用户可见文本到 .vue / .ts 文件中
- 禁止在模板中用字符串拼接

## 复数处理

使用 vue-i18n 的复数语法：

```ts
// 语言包
{
  item: "一个条目 | 多个条目" // 简单复数
}

// 使用
$tc("item", 1) // 一个条目
$tc("item", 2) // 多个条目
```

其他语言如有复杂复数变化，用 linked message 或选择格式。

## RTL / 方向支持

本项目暂不需要 RTL（阿拉伯语等），但布局上避免假设文本方向：

- 用 `start` / `end` 替代 `left` / `right`
- 图标翻转用 CSS 或条件判断

## 语言包体积优化

1. **按需加载**：默认语言包可随主包加载；语言包变大或语言数量增加时，改用动态 import。
2. **去除未使用 key**：定期清理不再使用的翻译 key。
3. **避免重复**：抽公共 key 到 `common` 命名空间。

## 常见坑

1. **不要在 setup 顶层直接用 `t()` 取响应式数据**：用 `computed` 包裹，确保语言切换时更新。
   ```ts
   // ❌ 错误：语言切换后不更新
   const title = t("home.title")

   // ✅ 正确
   const title = computed(() => t("home.title"))
   ```
2. **pages.json 中的标题**：`navigationBarTitleText` 是静态配置，不支持 i18n。需在 `onLoad` 中用 `uni.setNavigationBarTitle({ title: t(...) })` 动态设置。
3. **tabBar 文字**：tabBar 的 `text` 也是静态的。如需国际化 tabBar，用自定义 tabBar（成本较高，本项目暂不做）。
4. **遵循目标语言规范**：翻译时遵守对应语言的大小写、语序和标点规则。
