# 01 — 项目架构与目录规范

> 基于 uni-app 官方规范、Wot UI v2 工程实践、uview-plus / TDesign / NutUI 等高星项目的目录结构最佳实践沉淀。

## 设计原则

1. **按需支持多角色，单套部署**：不同角色是同一应用中的运行时视图。禁止为单个角色拆分独立应用或 monorepo。
2. **平台差异走条件编译，角色差异走运行时**：`#ifdef MP-WEIXIN` / `#ifdef H5` 只处理平台能力差异；角色差异通过 `auth` store 判断。
3. **主包轻量，分包承载业务**：Tab 页 + 公共页留主包（控制在 2MB 内），角色二级页全部进分包。
4. **领域驱动组织**：按业务领域（如 `resource`）而非技术类型（components、pages）组织深层模块，便于 spec coding 时定位。

## 新建文件时的命名约定

| 类型          | 命名风格                        | 示例                                                                 |
| ------------- | ------------------------------- | -------------------------------------------------------------------- |
| 组件/页面文件 | PascalCase + `.vue`             | `ResourceCard.vue`、`index.vue`（页面入口固定）                      |
| TS 工具/模块  | kebab-case                      | `use-pull-refresh.ts` → 实际用 camelCase 文件名：`usePullRefresh.ts` |
| composable    | `use` 前缀 + camelCase          | `usePagination.ts`                                                   |
| store         | 领域名 + camelCase              | `resource.ts`                                                        |
| 常量/枚举     | PascalCase 类名 + UPPER_CASE 值 | `ResourceStatus.PENDING`                                             |
| 图片资源      | kebab-case                      | `icon-home-active.png`                                               |

## pages.json 组织规则

1. **主包页面**放 `pages` 数组：登录、首页、我的、注册、重置密码等公共入口。
2. **分包**用 `subPackages` 声明：如 `pages/package-a` 与 `pages/package-b`。
3. **tabBar** 只包含主包页面：首页、我的。
4. **easycom** 规则：
   - `^wd-(.*)` → Wot UI v2 组件（已配置）
   - `^Home(.*)` → 首页区块
   - 新增业务组件规则遵循 `^前缀(.*)` 模式，便于按目录批量匹配
5. 新增页面必须同时更新 `pages.json`，**不要只建文件不注册路由**。

## 分包加载策略

- 登录后按权限和业务需要懒加载对应分包，降低主包体积。
- 公共依赖（Wot UI v2、pinia、i18n）留在主包，由 uni-app 自动处理共享。
- 主包体积预警线：1.5MB（微信小程序主包上限 2MB，预留 25% 缓冲）。

## Spec Coding 约定

> 本项目使用 Spec-driven 开发：每个功能先写 spec，再按 spec 实现。

- 每个页面/组件的 spec 文档放在对应目录的 `specs/` 子目录下（如 `pages/package-a/resource-form/specs/`）。
- spec 文件命名：`功能描述.spec.md`。
- spec 包含：需求描述、交互流程、UI 规格、接口契约、校验规则、边界情况。
