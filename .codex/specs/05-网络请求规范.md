# 05 — 网络请求规范

> 基于 uni-app request 封装、Wot UI v2 项目请求模式，参考 axios / vue-vben-admin 拦截器设计模式制定。

## 技术选型

- **请求库**：`uni.request` 原生封装（`src/api/request.ts`）
- **禁止引入 axios**：小程序端不支持 XMLHttpRequest，axios 无法运行

## 请求层架构

```
api/
├─ request.ts          # 核心封装：拦截器、错误处理、token 注入
├─ types/              # 接口类型定义
│  ├─ common.ts        #   通用类型（分页、响应体等）
│  ├─ auth.ts          #   认证相关类型
│  └─ resource.ts       #   示例资源相关类型
├─ auth.ts             # 认证接口
├─ resource.ts         # 示例资源接口
└─ task.ts             # 示例任务接口
```

## 统一响应结构

### 后端响应格式约定

```ts
interface ApiResponse<T> {
  code: number // 0 表示成功，非 0 表示业务错误
  message: string // 错误信息或成功提示
  data: T // 响应数据
}
```

### 分页响应格式

```ts
interface PageResponse<T> {
  list: T[]
  total: number
  page: number
  pageSize: number
}
```

## request.ts 核心功能

`src/api/request.ts` 必须提供以下能力：

1. **基础 URL 配置**：从 `import.meta.env.VITE_API_BASE_URL` 读取
2. **Token 自动注入**：Authorization: Bearer {token}
3. **响应拦截**：统一处理 code，自动 `resolve(data)` / `reject(error)`
4. **401 自动处理**：清除登录态 + 跳登录页
5. **请求超时**：默认 10 秒超时
6. **错误消息**：统一错误提示（可选，由调用方控制）

## 接口文件编写规范

每个业务领域一个接口文件，按资源分组：

```ts
// api/resource.ts
import { request } from "./request"
import type {
  ResourceListParams,
  ResourceListResponse,
  ResourceDetail,
  ResourceCreateParams,
} from "./types/resource"

/** 获取资源列表 */
export function getResourceList(params: ResourceListParams) {
  return request<ResourceListResponse>({
    url: "/resource/list",
    method: "GET",
    data: params,
  })
}

/** 获取资源详情 */
export function getResourceDetail(id: string) {
  return request<ResourceDetail>({
    url: `/resource/${id}`,
    method: "GET",
  })
}

/** 创建资源 */
export function createResource(data: ResourceCreateParams) {
  return request<{ id: string }>({
    url: "/resource/create",
    method: "POST",
    data,
  })
}
```

### 接口函数命名约定

| 操作              | 命名前缀              | 示例                                     |
| ----------------- | --------------------- | ---------------------------------------- |
| 查询（单个/列表） | `get*` / `fetch*`     | `getResourceList`、`fetchResourceDetail` |
| 创建              | `create*` / `add*`    | `createResource`                         |
| 更新              | `update*`             | `updateResource`                         |
| 删除              | `delete*` / `remove*` | `deleteResource`                         |
| 操作（动作类）    | 动词 + 名词           | `approveResource`、`cancelTask`          |

### 类型定义规范

```ts
// api/types/resource.ts

// ===== 请求参数 =====
export interface ResourceListParams {
  page: number
  pageSize: number
  keyword?: string
  status?: ResourceStatus
  dateRange?: [string, string]
}

export interface ResourceCreateParams {
  title: string
  category: string
  startDate: string
  content?: string
  ownerId: string
}

// ===== 响应数据 =====
export interface ResourceItem {
  id: string
  title: string
  category: string
  status: ResourceStatus
  startDate: string
  createTime: string
}

export interface ResourceDetail extends ResourceItem {
  content: string
  ownerName: string
  ownerDept: string
  tags?: string[]
  remark?: string
}

export type ResourceStatus = "draft" | "published" | "archived"

export interface ResourceListResponse {
  list: ResourceItem[]
  total: number
}
```

**规则**：

1. 所有接口参数和返回类型必须在 `api/types/` 中明确定义。
2. 枚举值用 `type` 联合类型定义，不用 `enum`（更轻量，可 tree-shake）。
3. 类型命名与接口函数对应，便于查找。

## 页面中调用接口

```vue
<script setup lang="ts">
import { ref, onMounted } from "vue"
import { getResourceList } from "@/api/resource"
import type { ResourceItem } from "@/api/types/resource"

const loading = ref(false)
const list = ref<ResourceItem[]>([])

async function loadData() {
  loading.value = true
  try {
    const data = await getResourceList({ page: 1, pageSize: 20 })
    list.value = data.list
  } catch (err) {
    // 错误由 request 层统一提示，此处处理业务逻辑
    console.error(err)
  } finally {
    loading.value = false
  }
}

onMounted(() => loadData())
</script>
```

## 错误处理

### 错误分类

| 错误类型   | 触发条件             | 处理方式                                       |
| ---------- | -------------------- | ---------------------------------------------- |
| 网络错误   | 断网、超时、DNS 失败 | request 层统一提示「网络异常，请检查网络连接」 |
| HTTP 错误  | 4xx/5xx 状态码       | request 层根据状态码处理                       |
| 401 未授权 | token 失效/过期      | 清除登录态，跳登录页                           |
| 业务错误   | code 非 0            | request 层 reject，调用方处理                  |

### 调用方错误处理

```ts
try {
  await submitForm(data)
  uni.showToast({ title: "提交成功", icon: "success" })
  uni.navigateBack()
} catch (err: any) {
  // 业务错误消息已在 request 层 showToast，此处只需处理逻辑
  // 如需自定义错误提示，传 silent: true 选项
}
```

## 请求取消与防抖

1. **页面卸载时取消未完成请求**：用 `AbortController` 或请求 ID 管理（uni.request 返回 requestTask）。
2. **搜索防抖**：输入框搜索用 300ms 防抖，避免频繁请求。
3. **防止重复提交**：按钮 loading 状态 + 请求锁。

## 环境变量

```
# .env.development
VITE_API_BASE_URL=/api
VITE_DEFAULT_LOCALE=zh-CN

# .env.production
VITE_API_BASE_URL=https://api.example.com
```

**规则**：

1. 环境变量必须以 `VITE_` 开头才能被 Vite 暴露到客户端。
2. 敏感信息（密钥、密码）不要放在环境变量中（会被打包进客户端）。
3. 新增环境变量需同时更新所有环境文件和类型声明（`env.d.ts`）。

## 安全规范

1. **HTTPS 优先**：生产环境必须使用 HTTPS。
2. **Token 安全**：token 只放 header 和 storage，不放 URL。
3. **敏感数据脱敏**：手机号、证件号等个人敏感信息按业务要求脱敏。
4. **CSRF 防护**：小程序端由微信域名校验保障，H5 端确保后端有 CSRF 防护。
5. **请求签名**：如后端要求，在 request 拦截器中统一加签。
