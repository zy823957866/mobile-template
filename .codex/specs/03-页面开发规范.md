# 03 — 页面开发规范

> 基于 uni-app 页面生命周期、Wot UI v2 页面模板模式，以及 TDesign 移动端页面最佳实践。

## 页面分类

| 类型       | 特点                             | 放置位置                                            |
| ---------- | -------------------------------- | --------------------------------------------------- |
| Tab 页     | tabBar 展示，常驻内存，首页/我的 | 主包 `pages/index`、`pages/mine`                    |
| 公共页     | 多角色共用，登录/注册/重置       | 主包 `pages/login`、`pages/register`、`pages/reset` |
| 业务二级页 | 分包业务功能页                   | 分包 `pages/package-a/*`、`pages/package-b/*`       |

## 页面文件结构

每个页面至少包含 `index.vue`，复杂页面可扩展：

```
pages/
└─ package-a/
   └─ resource-form/
      ├─ index.vue           # 页面主入口（必须）
      ├─ components/         # 页面内专用子组件
      │  └─ FileUpload.vue
      ├─ composables/        # 页面级组合式函数
      │  └─ useRegisterForm.ts
      ├─ specs/              # 页面 spec 文档
      │  └─ resource-form.spec.md
      └─ types.ts            # 页面类型定义
```

**规则**：只在一个页面使用的组件放页面内 `components/`，不要提到全局 `src/components/`。

## 页面生命周期使用规范

### uni-app 常用生命周期（双端通用）

| 钩子                  | 触发时机                     | 常见用途                  |
| --------------------- | ---------------------------- | ------------------------- |
| `onLoad(options)`     | 页面加载，参数来自路由 query | 初始化数据、获取 URL 参数 |
| `onShow()`            | 页面显示（每次显示都触发）   | 刷新列表数据、重置状态    |
| `onReady()`           | 页面初次渲染完成             | 获取节点信息、Canvas 操作 |
| `onHide()`            | 页面隐藏                     | 暂停定时器、取消请求      |
| `onUnload()`          | 页面卸载                     | 清理资源、移除监听        |
| `onPullDownRefresh()` | 下拉刷新                     | 刷新当前页数据            |
| `onReachBottom()`     | 上拉触底                     | 加载更多                  |
| `onShareAppMessage()` | 分享给朋友                   | 自定义分享内容            |

### 使用规则

1. **数据请求放 `onLoad` + `onShow`**：首次加载在 `onLoad`，需要每次刷新的数据放 `onShow`。
2. **列表页必须实现下拉刷新**：在 `pages.json` 中开启 `enablePullDownRefresh: true`。
3. **分页列表页必须实现上拉加载**：用 `onReachBottom` 或 `scroll-view` 的 `@scrolltolower`。
4. **清理工作放 `onUnload`**：定时器、事件监听、未完成的请求必须清理。
5. **不要依赖 `onMounted` 做页面级初始化**：小程序端页面组件的挂载时机与 H5 不同，用 `onLoad` 更可靠。

## 页面路由与导航

### 导航方式选择

| 方式           | API                | 适用场景                   | 目标页面  |
| -------------- | ------------------ | -------------------------- | --------- |
| 保留当前页跳转 | `uni.navigateTo`   | 从列表进详情               | 非 tab 页 |
| 重定向         | `uni.redirectTo`   | 表单提交后跳转，不允许返回 | 非 tab 页 |
| 切换 Tab       | `uni.switchTab`    | 底部 tab 切换              | tabBar 页 |
| 重启动         | `uni.reLaunch`     | 登录态失效后重进           | 任意页    |
| 返回           | `uni.navigateBack` | 返回上一页或多级           | —         |

### 路由参数规范

1. **简单参数走 URL query**：`?id=123&type=resource`，在 `onLoad(options)` 中解构。
2. **复杂数据不要走 URL**：通过 store 或 `getCurrentPages()` 传递，或 encode 后传递。
3. **参数类型明确**：URL 参数都是 string，使用时需显式转换（`Number()`、`JSON.parse()`）。
4. **参数命名用 camelCase**：与 JS 变量风格一致。

## 页面模板结构

标准页面布局结构：

```vue
<template>
  <PageContainer :loading="loading" :error="error" @retry="loadData">
    <!-- 页面内容 -->
    <view class="px-4 py-6">
      <!-- ... -->
    </view>
  </PageContainer>
</template>
```

### PageContainer 约定

`LayoutPageContainer`（L1 组件）统一处理：

- 加载状态（骨架屏/Loading）
- 错误状态（重试按钮）
- 空状态
- 安全区域适配（iOS 底部安全区）
- 页面背景色

## 数据加载模式

### 标准加载流程

```
onLoad → loading=true → 发起请求 → 成功/失败 → loading=false
                                 → 成功：渲染数据
                                 → 失败：显示错误页 + 重试
```

### 分页列表加载

```ts
// 标准分页状态
const loading = ref(false)
const finished = ref(false)
const page = ref(1)
const pageSize = ref(20)
const list = ref<any[]>([])

async function loadList() {
  if (loading.value || finished.value) return
  loading.value = true
  try {
    const data = await fetchList({ page: page.value, pageSize: pageSize.value })
    list.value.push(...data.list)
    finished.value = list.value.length >= data.total
    page.value++
  } finally {
    loading.value = false
  }
}
```

推荐使用 `composables/list/usePagination.ts` 封装分页逻辑。

## 条件区块化页面

首页等需要按权限、角色或用户状态展示不同内容的页面，采用**区块化**而非整页拆分：

```vue
<template>
  <view>
    <HomeShared />
    <!-- 公共区域 -->
    <HomeSectionA v-if="canShowSectionA" />
    <!-- 示例区块 A -->
    <HomeSectionB v-if="canShowSectionB" />
    <!-- 示例区块 B -->
  </view>
</template>
```

**为什么不拆成两个页面**：

1. tabBar 页面必须在主包，拆分会导致主包页面数增加
2. 权限或状态变化时无需重新跳转，体验更流畅
3. 公共区域代码不重复

## 页面性能优化

1. **首屏数据优先**：首屏关键数据先请求，非关键数据延迟加载。
2. **图片懒加载**：长列表中的图片必须加 `lazy-load`。
3. **setData 优化**：小程序端避免频繁 setData，合并更新。Vue 3 的响应式系统已大部分自动处理，但要注意频繁触发的 watcher。
4. **页面栈管理**：及时用 `redirectTo` 替代 `navigateTo` 避免页面栈过深（小程序最多 10 层）。
5. **下拉刷新 + 骨架屏**：提升加载体验感知。

## 页面间数据传递

| 场景                     | 方案                      |
| ------------------------ | ------------------------- |
| 简单参数（id、type）     | URL query + onLoad        |
| 表单草稿回传             | 事件总线 / 上一页实例获取 |
| 共享业务数据             | Pinia store               |
| 全局状态（登录态、语言） | Pinia store               |
