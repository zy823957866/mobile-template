# 移动端框架基础设施补全规划

> 调研对象：uni-app（40k+⭐）、Wot UI v2（4k+⭐）、uview-plus（6k+⭐）、TDesign（20k+⭐）、NutUI（8k+⭐）、Vant（23k+⭐）、vue-vben-admin（40k+⭐）、vitesse（30k+⭐）
>
> 适用范围：conti-visitor 移动端（H5 + 微信小程序）
>
> 当前状态：基础骨架已具备（uni-app + Vue3 + Vite + TS + Wot UI v2 + Pinia + UnoCSS + vue-i18n），但框架级基础设施和中间件体系尚未完善
>
> 文档目的：明确需要补全的框架能力，按优先级排序，给出每一项的实现方案和参考来源

## 三、补全项明细（按优先级）

### P0 — 核心基础设施（第一阶段，必须先做）

#### 1. 请求拦截器体系

**现状**：request.ts 只有基础的 token 注入和 401 处理，没有可插拔的拦截器机制。

**参考**：vue-vben-admin 的 axios 拦截器设计、Wot UI v2 的请求封装。

**需要补什么**：

- 可插拔的拦截器注册机制（addInterceptor / removeInterceptor）
- 内置拦截器：
  - `TokenInterceptor` — 请求前注入 token
  - `LoadingInterceptor` — 请求 loading（支持按请求控制）
  - `ErrorInterceptor` — 统一错误处理 + 错误码映射
  - `RetryInterceptor` — 网络失败自动重试（指数退避）
  - `CancelInterceptor` — 取消未完成请求（页面卸载时）
  - `LogInterceptor` — 开发环境请求日志
- 请求取消（AbortController / requestTask.abort）
- 重复请求防抖动（相同请求短时间内只发一次）
- 请求队列（并发数控制，避免同时发太多请求）

**文件结构**：

```
api/
├─ request.ts              # 核心封装（升级）
├─ interceptors/           # 拦截器目录
│  ├─ token.interceptor.ts
│  ├─ loading.interceptor.ts
│  ├─ error.interceptor.ts
│  ├─ retry.interceptor.ts
│  └─ log.interceptor.ts
└─ types/
   └─ request.ts           # 请求类型定义
```

---

#### 2. 全局错误处理 + 日志上报

**现状**：没有全局错误捕获，错误散落在各页面 try/catch 中。

**参考**：vue-vben-admin 的错误处理体系。

**需要补什么**：

- `app.config.errorHandler` — Vue 组件级错误捕获
- `uni.onError` — 全局 JS 错误
- `uni.onUnhandledRejection` — 未捕获的 Promise
- 错误分类：API 错误 / 业务错误 / 系统错误 / 用户操作错误
- 错误消息映射：错误码 → 用户友好文案
- 错误上报接口（预留，生产环境接入监控平台）
- 错误边界组件（ErrorBoundary），包裹页面避免白屏

**文件结构**：

```
core/
└─ error/
   ├─ index.ts             # 入口：注册全局错误监听
   ├─ handler.ts           # 错误处理逻辑
   ├─ mapper.ts            # 错误码 → 文案映射
   └─ report.ts            # 错误上报
```

---

#### 3. 统一交互服务（Toast / Modal / Loading）

**现状**：页面中直接调用 `uni.showToast` 等，没有统一封装。

**参考**：Wot UI v2 的 useToast / useDialog、uview-plus 的 $u 工具。

**需要补什么**：

- `ToastService` — 统一的消息提示（success / error / warning / info / loading）
- `ModalService` — 确认弹窗、输入弹窗、自定义内容弹窗
- `LoadingService` — 全局 loading 管理（计数防闪烁，多个请求同时 loading 不会闪烁）
- 支持 i18n 多语言
- 样式与 Wot UI v2 主题对齐

**文件结构**：

```
services/
├─ toast.service.ts
├─ modal.service.ts
└─ loading.service.ts
```

#### 4. 页面容器组件（PageContainer）

**现状**：每个页面自己处理 loading / error / empty 状态，重复代码多。

**参考**：TDesign 的 PageContainer、vue-vben-admin 的 Page 组件。

**需要补什么**：

- `LayoutPageContainer` 组件，统一处理：
  - loading 状态（骨架屏 / loading 圈）
  - error 状态（错误提示 + 重试按钮）
  - empty 状态（空状态插画 + 文案）
  - 安全区域适配（iOS 底部安全区）
  - 页面背景色
  - 下拉刷新（可选）
- 骨架屏组件（`SkeletonList` / `SkeletonCard` 等）

**文件结构**：

```
components/
└─ layout/
   ├─ PageContainer.vue
   ├─ SkeletonList.vue
   └─ EmptyState.vue
```

---

#### 5. App Store + User Store

**现状**：只有 auth store，缺少应用级和用户级状态。

**参考**：vue-vben-admin 的 app / user store。

**需要补什么**：

- `app store` — 全局应用状态：
  - locale（语言）
  - theme（主题模式）
  - deviceInfo（设备信息）
  - networkStatus（网络状态）
  - appVersion（版本号）
- `user store` — 用户信息：
  - profile（用户资料）
  - permissions（权限列表）
  - settings（用户设置）
- Store 持久化策略（哪些需要存 storage，哪些不需要）

**文件结构**：

```
store/
├─ auth.ts     # 已有
├─ app.ts      # 新增
└─ user.ts     # 新增
```

#### 7. 通用校验工具库

**现状**：没有统一的校验工具，表单校验散落在各页面。

**参考**：uview-plus 的校验工具、async-validator。

**需要补什么**：

- 通用校验函数：isEmpty / isPhone / isEmail / isIdCard / isCarPlate
- 与 wd-form 的 async-validator 集成的自定义校验器
- 中文姓名、港澳台身份证等边缘 case

**文件结构**：

```

```

#### 8. 路由增强（RouterService）

**现状**：routeGuard 只有登录校验，缺少完整的路由能力。

**参考**：vue-router 的导航守卫模式、uni-app 拦截器 API。

**需要补什么**：

- 封装统一的路由跳转方法（navigateTo / redirectTo / switchTab / reLaunch / navigateBack）
- 路由参数解析（自动转类型、默认值）
- 守卫链：支持多个中间件式守卫（洋葱模型）
- 内置守卫：
  - `authGuard` — 登录校验
  - `roleGuard` — 角色校验
  - `titleGuard` — 自动设置页面标题（i18n）
  - `analyticsGuard` — 页面访问埋点
- 路由白名单配置
- 页面栈深度监控（小程序最多 10 层）

**文件结构**：

```
core/
└─ router/
   ├─ index.ts             # 路由服务入口
   ├─ guard.ts             # 守卫链
   └─ guards/
      ├─ auth.guard.ts
      ├─ role.guard.ts
      ├─ title.guard.ts
      └─ analytics.guard.ts
```

#### 9. Storage 增强

**现状**：storage.ts 只有简单的 get/set/remove。

**参考**：vue-vben-admin 的 cache 工具。

**需要补什么**：

- 命名空间（`conti:` 前缀，避免与其他小程序 storage 冲突）
- 过期时间（TTL）支持
- 类型安全（泛型 + 默认值）
- 批量操作（clearAll / getMultiple）
- 存储容量监控（小程序 storage 上限 10MB）
- 加密存储（敏感数据可选加密）

---

#### 10. 主题设计 Token 系统

**现状**：只有少量 CSS 变量，没有完整的设计 token。

**参考**：TDesign 设计 token、Wot UI v2 的 CSS 变量体系。

**需要补什么**：

- 完整的 CSS 变量体系：
  - 颜色系统：主色（5 级深浅）、功能色（成功/警告/错误/信息）、中性色（10 级灰度）
  - 字体系统：字号（6 级）、行高、字重
  - 间距系统：4/8/12/16/20/24/32/48
  - 圆角系统：4/8/12/16/24/圆形
  - 阴影系统：3 级阴影
  - 动效系统：缓动函数、动画时长
- 与 UnoCSS theme 配置一一对应
- 与 Wot UI v2 的 CSS 变量对齐（`--wot-*`）
- SCSS 变量版本（用于 scoped 样式）

**文件结构**：

```
styles/
├─ tokens/
│  ├─ color.css            # 颜色 token
│  ├─ typography.css       # 字体 token
│  ├─ spacing.css          # 间距 token
│  └─ motion.css           # 动效 token
├─ variables.scss          # SCSS 版本
└─ global.scss             # 全局样式
```
